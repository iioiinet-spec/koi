펜윅 트리 Fenwick Tree (BIT) 완전정복

비트 하나로 구간 합과 값 갱신을 모두 O(log N)에 — Binary Indexed Tree

왜 펜윅 트리가 필요할까?

배열에서 "구간 합 질의"와 "값 갱신"이 섞여서 M번 들어오는 문제(대표: 백준 2042 구간 합 구하기)를 생각해 봅시다.

방법구간 합 질의값 갱신M번 처리 총 시간
그냥 배열O(N)O(1)O(NM) — 시간 초과
누적 합(prefix sum)O(1)O(N) (뒤를 전부 다시 계산)O(NM) — 시간 초과
펜윅 트리O(log N)O(log N)O(M log N) — 통과!

누적 합은 질의가 빠르지만 갱신이 느리고, 배열은 그 반대입니다. 펜윅 트리는 둘 사이의 균형점입니다.

핵심 열쇠: lowbit — i & -i

lowbit(i)는 i를 이진수로 썼을 때 가장 낮은(오른쪽) 1비트가 나타내는 값입니다.

  • lowbit(6) : 6 = 0110₂ → 가장 낮은 1비트는 2의 자리 → lowbit = 2
  • lowbit(12) : 12 = 1100₂ → 4
  • lowbit(8) : 8 = 1000₂ → 8, lowbit(7) : 0111₂ → 1

코드로는 i & -i 한 줄입니다. 컴퓨터는 음수를 2의 보수로 표현하는데, -i는 i의 비트를 뒤집고 1을 더한 것이라 가장 낮은 1비트와 그 아래만 일치합니다. 그래서 AND를 하면 딱 그 비트만 남습니다.

예: i = 6 = 0110₂, -6 = 1010₂(4비트 기준) → 0110 & 1010 = 0010₂ = 2 ✓

tree[i]는 무엇을 저장하나? — 담당 구간

펜윅 트리의 tree[i]는 원본 배열의 구간 [ i − lowbit(i) + 1 , i ]의 합을 저장합니다. 즉 각 인덱스가 자기 lowbit 길이만큼의 구간을 담당합니다.

예제 배열 a = [3, 2, 5, 1, 4, 6, 2, 7] (1번부터)일 때:

i이진수lowbit담당 구간tree[i] 저장 값
100011a[1]3
200102a[1..2]3+2 = 5
300111a[3]5
401004a[1..4]3+2+5+1 = 11

배열 하나(tree[1..N])만으로 트리 구조를 표현하므로 메모리도 세그먼트 트리(약 4N)보다 훨씬 적습니다.

질의 query(i): lowbit를 빼며 내려간다

구간 [1..i]의 합은, i에서 시작해 i -= i & -i 를 반복하며 만나는 tree 값들을 모두 더하면 됩니다. 담당 구간들이 겹치지 않고 [1..i]를 정확히 덮기 때문입니다.

예: query(7) — 구간 [1..7]의 합

  • i = 7 (0111₂) : tree[7] = a[7] 더함 → i = 7 − 1 = 6
  • i = 6 (0110₂) : tree[6] = a[5..6] 더함 → i = 6 − 2 = 4
  • i = 4 (0100₂) : tree[4] = a[1..4] 더함 → i = 4 − 4 = 0, 종료

합 = 2 + 10 + 11 = 23. 방문 횟수 = i의 이진수에서 1의 개수 ≤ log₂N → O(log N)

갱신 update(i, +d): lowbit를 더하며 올라간다

a[i]가 바뀌면 i를 담당 구간에 포함하는 모든 tree 노드를 고쳐야 합니다. 그런 노드들은 i += i & -i 를 반복하며 정확히 찾아집니다 (i ≤ N인 동안).

예: update(3, +5) — a[3]에 5를 더하기

  • i = 3 : tree[3] += 5 → i = 3 + 1 = 4
  • i = 4 : tree[4] += 5 → i = 4 + 4 = 8
  • i = 8 : tree[8] += 5 → i = 8 + 8 = 16 > N, 종료

질의와 갱신이 완벽히 대칭입니다: 질의는 빼기(↓), 갱신은 더하기(↑).

임의 구간 [l..r]의 합

펜윅 트리의 query는 항상 [1..i] 접두사 합입니다. 임의 구간은 두 번의 질의로 계산합니다:

sum(l..r) = query(r) − query(l − 1)

query(l)이 아니라 query(l − 1)을 빼야 a[l]이 살아남습니다. 정올 단골 실수!

펜윅 트리 vs 세그먼트 트리

선택 기준: "구간 합 + 점 갱신"이면 무조건 펜윅. 구간 최솟값/최댓값처럼 뺄셈으로 되돌릴 수 없는 연산이면 세그먼트 트리를 씁니다.

방문 경로

    C++ 표준 구현 — 백준 2042 스타일

    fenwick.cpp 
    #include <bits/stdc++.h>
using namespace std;

int N;
long long tree[1000001];      // 1-indexed! tree[0]은 사용하지 않음
long long a[1000001];         // 원본 값 보관 ("값을 x로 변경" 처리용)

void update(int i, long long d) {   // a[i] += d
    for (; i <= N; i += i & -i)      // lowbit를 더하며 위로
        tree[i] += d;
}

long long query(int i) {             // [1..i]의 합
    long long s = 0;
    for (; i > 0; i -= i & -i)       // lowbit를 빼며 아래로
        s += tree[i];
    return s;
}

long long rangeSum(int l, int r) {   // [l..r]의 합
    return query(r) - query(l - 1);  // ★ l-1 주의!
}

int main() {
    int M; scanf("%d %d", &N, &M);
    for (int i = 1; i <= N; i++) {
        scanf("%lld", &a[i]);
        update(i, a[i]);              // 초기 트리 구성: O(N log N)
    }
    while (M--) {
        int t; scanf("%d", &t);
        if (t == 1) {                 // a[i]를 x로 "변경"
            int i; long long x; scanf("%d %lld", &i, &x);
            update(i, x - a[i]);      // ★ 차이만큼 더한다
            a[i] = x;
        } else {                      // [l..r] 구간 합 출력
            int l, r; scanf("%d %d", &l, &r);
            printf("%lld\n", rangeSum(l, r));
        }
    }
}

    핵심 두 줄만 외우세요: 갱신은 i += i & -i (i ≤ N 동안), 질의는 i -= i & -i (i > 0 동안). 나머지는 전부 이 대칭에서 나옵니다.

    Python 구현

    fenwick.py 
    import sys
input = sys.stdin.readline

N, M = map(int, input().split())
tree = [0] * (N + 1)          # 1-indexed

def update(i, d):
    while i <= N:
        tree[i] += d
        i += i & -i

def query(i):                 # [1..i] 합
    s = 0
    while i > 0:
        s += tree[i]
        i -= i & -i
    return s

a = [0] * (N + 1)
for i in range(1, N + 1):
    a[i] = int(input())
    update(i, a[i])

for _ in range(M):
    t, x, y = map(int, input().split())
    if t == 1:                # a[x]를 y로 변경
        update(x, y - a[x])
        a[x] = y
    else:                     # [x..y] 구간 합
        print(query(y) - query(x - 1))

    응용: 구간 갱신 + 점 질의 (차이 배열 트릭)

    "[l..r] 전체에 d 더하기 + a[i] 하나의 값 묻기" 유형은 차이(계차) 배열에 펜윅을 씌우면 됩니다.

    // 구간 [l, r]에 d 더하기
update(l, d);  update(r + 1, -d);
// a[i]의 현재 값 = 처음 값 + query(i)

    구간 갱신 + 구간 질의까지 필요하면 펜윅 트리 2개를 쓰는 확장이 있지만, 정올 수준에서는 위 두 형태(점 갱신+구간 합, 구간 갱신+점 질의)가 대부분입니다.

    추천 연습 문제

    문제유형
    백준 2042 — 구간 합 구하기점 갱신 + 구간 합 (기본형, 위 코드 그대로)
    백준 11658 — 구간 합 구하기 32차원 펜윅 트리
    백준 1275 — 커피숍2값 변경(차이 갱신) 연습
    백준 2517 — 달리기좌표 압축 + 펜윅으로 순위 세기 (정올 빈출 패턴)

    정올에서 자주 나오는 실수 6가지

    ① 0번 인덱스 사용

    lowbit(0) = 0이라 i += i & -i가 영원히 제자리 — 무한 루프에 빠지거나 tree[0]만 계속 갱신됩니다. 펜윅 트리는 반드시 1-indexed로! 입력이 0-indexed라면 전부 +1 해서 넣으세요.

    ② 구간 합을 query(r) − query(l)로 계산

    이러면 a[l]이 빠집니다. 정답은 query(r) − query(l − 1). "l의 왼쪽 끝을 살리려면 l−1까지를 뺀다"로 기억하세요.

    ③ "값을 x로 변경"인데 x를 그대로 더함

    펜윅의 update는 더하기(+d)입니다. 변경 문제(백준 2042 등)에서는 update(i, x − a[i]); a[i] = x; 처럼 차이만큼 더해야 합니다. 원본 배열 a를 따로 유지하는 것을 잊지 마세요.

    ④ 루프 경계 실수

    갱신은 i <= N인 동안(N 넘으면 종료), 질의는 i > 0인 동안입니다. 방향과 조건이 뒤바뀌면 배열 범위 밖 접근이나 무한 루프가 납니다.

    // ✗ 틀림 — 방향 반대
void update(int i, long long d){ for(; i > 0; i -= i & -i) tree[i] += d; }
// ✓ 맞음
void update(int i, long long d){ for(; i <= N; i += i & -i) tree[i] += d; }

    ⑤ int 오버플로

    N ≤ 10⁶, |값| ≤ 10⁹이면 합이 최대 10¹⁵로 int 범위를 훨씬 넘습니다. tree, 누적 합, 출력 모두 long long(%lld)으로!

    ⑥ tree 배열 크기를 N으로 선언

    1-indexed이므로 tree[N + 1] 크기가 필요합니다. 전역 배열이면 문제 최대 크기 + 1로 넉넉하게 선언하세요. (지역 변수로 큰 배열을 만들면 스택 오버플로 — 전역 또는 vector로!)

    암기 카드: "1-indexed · query(l−1) 빼기 · 변경은 차이로 · 갱신 ↑ i≤N, 질의 ↓ i>0 · long long · 크기 N+1" — 여섯 개만 지키면 펜윅은 10줄 무기입니다!
