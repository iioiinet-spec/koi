준비
서로 다른 주사위 두 개를 던질 때 나오는 눈의 쌍은 모두 몇 가지인가? (답: 6 × 6 = 36가지)

빨간 주사위와 파란 주사위를 던집니다. 나온 눈의 합이 4의 배수가 되는 경우는 몇 가지일까요?

36가지를 모두 적어 보는 것도 방법이지만, 합이 4, 8, 12인 경우로 나누어 세면 훨씬 빠릅니다. 이때 나눈 경우들이 서로 겹치지 않는지 반드시 확인해야 합니다. 합이 4이면서 동시에 8일 수는 없으므로 겹치지 않고, 그래서 그냥 더하면 됩니다.

이 주제의 두 도구
합의 법칙 — 겹치지 않는 경우로 나누어 더한다.　곱의 법칙 — 단계로 쪼개어 곱한다.
경우의 수 문제는 대부분 이 둘을 어떻게 섞어 쓰는지의 문제입니다.

1. 합의 법칙

합의 법칙
일이 일어나는 경우를 동시에 일어날 수 없는 두 경우 A, B로 나눌 수 있고 각각 m가지, n가지라면, 전체 경우의 수는 m + n이다. 셋 이상으로 나누어도 같다.

1~50 중 4의 배수 또는 6의 배수4의 배수, 6의 배수겹침이 있어 그냥 더하면 안 된다

“또는”이 나오면 무조건 더하는 것이 아닙니다. 두 경우가 겹치면 겹치는 만큼 빼야 합니다. 1~50에서 4의 배수 12개 + 6의 배수 8개 − 12의 배수 4개 = 16개입니다. 겹치지 않게 나누는 것이 합의 법칙의 핵심 조건입니다.

2. 곱의 법칙과 수형도

곱의 법칙
일이 단계로 나뉘고, 앞 단계를 어떻게 고르든 다음 단계의 선택지가 항상 n가지라면, 전체 경우의 수는 각 단계의 선택지 수를 곱한 값이다.

빵 2가지, 음료 3가지 중 하나씩 고르는 방법은 2 × 3 = 6가지입니다. 수형도로 그리면 왜 곱하는지 보입니다.

주의 · 앞 선택이 뒤에 영향을 줄 때
“1~9에서 서로 다른 숫자 세 개로 세 자리 비밀번호 만들기”는 9 × 9 × 9가 아니라 9 × 8 × 7 = 504입니다. 앞에서 쓴 숫자를 다시 못 쓰므로 선택지가 줄어듭니다. 줄어드는 개수가 일정하면 곱의 법칙을 그대로 씁니다.

같은 일을 하는 두 프로그램
C
#include <stdio.h>

int main(void) {
    int c4 = 0, c3 = 0, odd = 0;
    for (int a = 1; a <= 6; a++)
        for (int b = 1; b <= 6; b++) {
            if ((a + b) % 4 == 0) c4++;
            if ((a + b) % 3 == 0) c3++;
            if ((a * b) % 2 == 1) odd++;
        }
    printf("합이 4의 배수: %d\n", c4);
    printf("합이 3의 배수: %d\n", c3);
    printf("곱이 홀수: %d, 곱이 짝수: %d\n", odd, 36 - odd);
    return 0;
}

②개념과 정리

1. 계승 n!과 순열 nPr

정의
n! = n × (n − 1) × … × 2 × 1 (0! = 1로 약속)
서로 다른 n개에서 r개를 골라 순서 있게 늘어놓는 방법의 수를 nPr이라 하고, nPr = n × (n − 1) × … × (n − r + 1) = n! ÷ (n − r)!이다.

3. 같은 것이 있는 순열

정리
전체 n개 중 같은 것이 각각 a개, b개, … 있을 때, 한 줄로 배열하는 방법은 n! ÷ (a! × b! × …)이다.

왜 나눌까요? 같은 글자에 잠시 번호를 붙여 모두 다르다고 보면 n!가지입니다. 그런데 번호를 지우면 여러 배열이 하나로 합쳐집니다. A가 3개라면 A₁A₂A₃의 자리를 바꾼 3! = 6가지가 모두 같은 배열이 되므로, 같은 배열을 6번씩 세었던 것입니다. 그래서 6으로 나눕니다.

void swap(char *a, char *b) { char t = *a; *a = *b; *b = t; }

int next_perm(char *s, int n) {   /* 사전순 다음 배열 */
    int i = n - 2;
    while (i >= 0 && s[i] >= s[i+1]) i--;
    if (i < 0) return 0;            /* 마지막 배열 */
    int j = n - 1;
    while (s[j] <= s[i]) j--;
    swap(&s[i], &s[j]);
    for (int a = i+1, b = n-1; a < b; a++, b--)
        swap(&s[a], &s[b]);         /* 뒤를 오름차순으로 */
    return 1;
}

def next_perm(s):
    s = list(s); n = len(s); i = n - 2
    while i >= 0 and s[i] >= s[i+1]:
        i -= 1
    if i < 0:
        return None                 # 마지막 배열
    j = n - 1
    while s[j] <= s[i]:
        j -= 1
    s[i], s[j] = s[j], s[i]
    s[i+1:] = reversed(s[i+1:])     # 뒤를 오름차순으로
    return "".join(s)

2. 덧셈 표 — 각 칸에 그 점까지의 경로 수를 적는다

단계하는 일
1출발점에 1을 적는다.
2맨 아래 줄과 맨 왼쪽 줄은 가는 길이 하나뿐이므로 모두 1을 적는다.
3나머지 칸은 왼쪽 칸 + 아래 칸을 적는다.
4도착점의 수가 답이다.
왜 더하는가
어떤 점 P에 도착하기 바로 직전에는 P의 왼쪽 점이나 아래 점 중 하나에 있어야 한다. 이 두 경우는 겹치지 않고 빠짐도 없으므로, 합의 법칙에 의해 (P까지의 경로 수) = (왼쪽 점까지의 경로 수) + (아래 점까지의 경로 수)이다.

파스칼 삼각형에서 “위 두 수를 더하는” 것과 같은 규칙입니다. 실제로 대각선 방향으로 읽으면 두 표에 같은 수가 나타납니다.

출발점에서 점 P까지 가는 최단경로의 수를 f(P)라 하자. 표의 각 칸에 f(P)를 적는다는 것을 보이면 된다.

출발점 출발점에 가는 방법은 “아무 데도 가지 않는 것” 하나뿐이므로 f(출발점) = 1이다.

맨 아래 줄과 맨 왼쪽 줄 오른쪽과 위쪽으로만 갈 수 있으므로, 맨 아래 줄의 점에는 계속 오른쪽으로만, 맨 왼쪽 줄의 점에는 계속 위쪽으로만 가는 길 하나뿐이다. 그래서 모두 1이다.

나머지 점 P P에 도착하기 바로 직전에 어디에 있었는지 생각한다. 마지막 이동은 오른쪽 한 칸 또는 위쪽 한 칸이므로, 직전 위치는 P의 왼쪽 점 L 또는 P의 아래 점 D뿐이다.

  • 겹치지 않는다: 한 경로의 마지막 이동은 오른쪽이거나 위쪽이거나 하나로 정해지므로, 같은 경로가 두 경우에 동시에 들어갈 수 없다.
  • 빠짐이 없다: P로 가는 어떤 경로든 마지막 이동이 둘 중 하나이므로 반드시 한쪽에 들어간다.

또 L까지 가는 경로 하나에 “오른쪽 한 칸”을 붙이면 P까지 가는 경로가 하나 만들어지고, 거꾸로 마지막이 오른쪽인 P까지의 경로에서 마지막 이동을 지우면 L까지의 경로가 하나 나온다. 곧 두 가지가 하나씩 짝지어지므로 그 개수는 f(L)로 같다. 아래쪽도 마찬가지로 f(D)이다.

따라서 합의 법칙에 의해 f(P) = f(L) + f(D)이고, 이것이 표에서 왼쪽 칸과 아래 칸을 더하는 이유이다. 출발점부터 차례로 채우면 모든 칸이 그 점까지의 경로 수가 된다.
